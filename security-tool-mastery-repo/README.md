# Cloud Security Tool Mastery Project

Open-source security tooling applied to the Terraform from the Task 2 lab
(a segmented AWS VPC, IAM, encrypted S3, CloudTrail/CloudWatch).

**Constraint, stated up front:** no live cloud account was available (AWS, GCP
and Azure signups all stalled on payment verification). So:

| What | Run against | Real or simulated |
|---|---|---|
| Checkov (IaC misconfiguration scan) | the Terraform in this repo | **real tool, real output** |
| detect-secrets (secrets scan) | this repo | **real tool, real output** |
| `detection/detect.py` (log analysis) | `sample_cloudtrail.json` | **my own script on SYNTHETIC events** |
| Prowler, GuardDuty, Security Hub, IAM Access Analyzer | - | identified in the report, **not run** (need a live account) |

The synthetic CloudTrail events are generated by `detection/generate_sample_logs.py`
(AWS docs example account `111122223333`, RFC 5737 test IPs). They are not real telemetry.

## Layout

```
terraform-baseline/   Task 2 code, unchanged           -> Checkov: 90 passed / 27 failed
terraform-hardened/   remediated version               -> Checkov: 261 passed / 0 failed / 13 skipped (justified inline)
detection/            synthetic log generator + rule-based detector
scans/                raw tool output (JSON + text)
docs/                 chart used in the report
.github/workflows/    CI: runs Checkov + secrets scan + detector self-test (written, not yet run on GitHub)
```

## Reproduce

```bash
pip install checkov==3.3.27 detect-secrets==1.5.0

checkov -d terraform-baseline --framework terraform --compact   # 27 failed
checkov -d terraform-hardened --framework terraform --compact   # 0 failed, 13 skipped

detect-secrets scan --all-files --exclude-files "^scans/"                               # 0 files flagged

cd detection
python3 generate_sample_logs.py                                  # writes sample_cloudtrail.json (412 events)
python3 detect.py sample_cloudtrail.json                         # 7 findings
```

(Checkov prints a harmless warning if it cannot reach the Prisma Cloud API; scanning is local.)

## Results

| | Baseline | Hardened |
|---|---|---|
| Failed checks | 27 | 0 |
| Skipped (accepted risk, justification in the `.tf` comment) | 0 | 13 |
| Resources scanned | 27 | 61 |

Of the 27 baseline failures, 21 were fixed in code and 6 are accepted with a written reason.
The other 7 skips in the hardened version are on resources the fixes introduced
(the KMS key policy and the S3 access-log bucket). Pass counts are not comparable
between the two columns because the hardened version defines more resources.

## Limits

- `terraform validate` / `plan` were **not** run (the Terraform binary could not be downloaded in the build
  environment). The code parses as HCL and Checkov parsed all 61 resources with 0 parsing errors, but it has never been applied.
- Checkov is static analysis: it reads the code, not a running account.
- Detection thresholds were tuned on the same synthetic data they are tested on, so the 7-for-7 result shows the
  rules work as written, not how they would perform on real traffic.
